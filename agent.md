# PDF-YZ — Agent Guide

> PDF editor: Rust core compiled to WebAssembly, Astro interface, Tauri desktop shell.
> Hosted at `app.zigmoon.com/PDF-YZ/`. Language: **English**.

---

## 0. Where the code lives now

The repository holds three folders, and **they are not interchangeable**:

| Folder | Role | Output |
|---|---|---|
| `pdfyz-rust/` | calculation core — geometry, colour, imposition, z-order, sessions. **Zero external crates.** | `pdfyz_core.wasm` (~155 KB) |
| `pdfyz-astro/` | the interface. 16 CSS slices, 19 components, one page. The editor logic is `src/scripts/app.js`, migrated verbatim. | `dist/` (static site) |
| `pdfyz-desktop/` | Tauri 2 shell around that site. | installers for Windows / macOS / Linux |

**`index.html` is frozen.** It is the behaviour reference and the input of
`pdfyz-astro/tools/split-legacy.mjs`; it is no longer edited. A UI change is made
in `pdfyz-astro/src/`, never in `index.html` — otherwise the two drift and the next
`split-legacy.mjs --force` silently reverts it.

`src/scripts/app.js` is likewise a **copy**, generated once by the splitter and
then hand-edited (that is what `--check` protects: it refuses to overwrite it).
Edit it in place, in `pdfyz-astro/`.

Two rules that are easy to break and expensive to debug:

1. **Nothing is fetched at runtime** — with one stated exception, the optional
   Google Families described below. Every other third-party file is vendored into
   `pdfyz-astro/public/vendor/` by `tools/vendor-cdn.mjs`. A service worker is not a
   substitute: it does not register inside a Tauri webview, so cache-on-first-visit
   leaves the desktop app dead offline.
2. **Rust and JavaScript must agree.** The JS fallback stays in the app, so every
   rule ported to Rust is re-implemented in `pdfyz-rust/scripts/validate-wasm.mjs`
   and compared (206 checks). A change to `pdfyz-core` without a matching check is
   an untested change.

### The hand-written files

`src/styles/01…16` are slices of `index.html`, regenerated by the splitter.
Everything the splitter must not overwrite is declared in `tools/split-legacy.mjs`,
in one of three lists — that is what makes a `--force` safe:

| List | Contents | Why |
|---|---|---|
| `HAND_WRITTEN_STYLES` | `17-prehome.css`, `18-theme.css` | imported after the slices |
| `HAND_WRITTEN_SCRIPTS` | `../scripts/theme.js` | imported before `app.js` |
| `src/scripts/app.js` | the editor module | carries the Rust kernel wiring |

They override by cascade only — same specificity, later file — so there is no
`!important` anywhere. Deleting a redesign means deleting one list entry.

`CSS_SEGMENTS` stores **offsets from the `<style>` line**, not absolute line
numbers: adding a line in `<head>` used to shift the whole file and fail the split
on fifteen slices at once. `BODY_SEGMENTS` anchors on text for the same reason.

### Theme

Day is the **default**; nothing reads `prefers-color-scheme`. The saved choice lives
in `localStorage['pdfz-theme']` — deliberately not in `pdfz-prefs`, which `app.js`
rewrites wholesale. A blocking script at the top of `<head>` sets
`<html data-theme>` before the first paint, so there is no light flash.

`data-theme` on the root element is the single switch: `18-theme.css` redefines the
tokens, and every surface built on them — toolbar, panels, modals, canvas, mobile
chrome — follows without a rule of its own. The accent inverts from near-black to
white, which means any rule written as `color: #fff` on `var(--accent)` must become
`var(--accent-contrast)`; the dark block fixes the handful that exist.

The pre-home declares its own `--pre-*` tokens twice (day, then
`:root[data-theme="dark"]`), because its palette is a designed surface rather than a
generic one. Its greys are chosen for measured contrast, not by eye: 6.5:1 and
4.7:1 in day, 8.0:1 and 5.3:1 at night.

### The one deliberate network call

`loadGoogleFont()` in `app.js` fetches `fonts.googleapis.com` when the user picks one of
the optional families in the text tool. Those families are **not** vendored: they exist
only to be embedded into an exported PDF, and bundling every weight would add several
megabytes to a 6.5 MB site.

This is the single exception to "nothing is fetched at runtime", and it is guarded:
`navigator.onLine === false` short-circuits to an explicit message naming the font,
rather than a silent failure — which is what the desktop build would otherwise show.
`tools/verifie-livraison.mjs` accepts this one URL and fails on any other in the bundle.

### The icon

`favicon.svg` and `logo-pdf-yz.svg` carry the **mark alone**: five white pages,
each with a black outline, on a transparent square. No badge, no background — the
dark pre-home is the background. The frame is fitted to the real bounding box
(410.66 × 490.15), so the mark fills 96.9 % of the height and 81.3 % of the width:
the maximum a portrait mark can occupy in a square without distortion.

Do not re-export the Illustrator file: it carries ~100 KB of hidden layers. The two
SVGs are byte-identical; `pdfyz-astro/public/icons/*.png` are rasterised from them
(32, 180, 192, 512 for the manifest, plus a 512 *maskable* variant whose ink is
fitted inside Android's 80 % safe circle). Regenerate the Tauri icons with
`npx tauri icon ../favicon.svg` — never by hand.

## 4. Persistence

| Key | Format | TTL | Purpose |
|---|---|---|---|
| `pdfz-meta` | JSON `{fileName, timestamp, pages, elements, paths}` | 7 days | **legacy** single-slot autosave (kept for backward compat) |
| `pdfz-pdf` | base64 (32 KB chunked btoa) | 7 days | **legacy** PDF bytes (skipped if > 10 MB) |
| `pdfz-sessions` | JSON `[{id, fileName, timestamp, pages, size}]` | 7 days | lightweight session **index** for the pre-home list |
| `pdfyz-sessions` (IndexedDB, store `docs`) | `{id, fileName, timestamp, pages, size, elements, paths, bytes}` | 7 days | real payload of **every** session → makes Resume work for all of them |
| `pdfz-prefs` | JSON | none | user prefs |
| `pdfz_donated_v1` | `'1'` | none | unlock install gate |

- `autoSave()` is triggered by `markDirty()` on a 2s debounce. `restore()` → `restoreSession(id)`.
- **Session id** = `_sessionId(fileName)` = `'doc:' + name.toLowerCase()`. One entry per document name.
- **`hasPdf` is never persisted.** Availability is derived at boot by `_scanSessionBytes()`
  (IndexedDB key cursor, never loads the blobs) plus the legacy `pdfz-meta`/`pdfz-pdf` slot.
  Storing it as a flag used to advertise payloads that had never been written.
- `_flushSession` is debounced 900 ms; `saveElementsMeta` refreshes only the edit layer
  (bytes are kept from the previous record), `savePdfBytes` writes the bytes when they changed.
  A `visibilitychange → hidden` handler flushes the latest edit layer.
- `_pruneSessions()` runs at boot: drops entries older than `SESSION_TTL`, deletes their IndexedDB
  records, caps at `MAX_SESSIONS = 12`, and rewrites the index with normalised ids.

## 5. Loading UX (do not regress)

- **Splash 0–100% bar** while no document is open ([beginSplashProgress](index.html#L2605)).
- **In-app loader overlay** `#loader` once the splash is hidden ([beginLoaderProgress](index.html#L2648)).
- `openPDF` drives a single progress source switching between the two depending on splash visibility.
- `extractPageText` (80) and `extractPageImages` (4) yield via `_uiYield()` to keep the UI responsive on big PDFs.
- `_isOpening` lock prevents concurrent opens (toast: "Already loading a PDF…").
- `_setSplashBusy(on, msg)` is the **only** place that toggles the pre-home loading state
  (`.splash-busy` on `#splash`, `.visible` on `#splashLoading`); never hide the drop zone with inline
  styles, or the session pane will stay clickable mid-load.
- `appendPDF` and `rebuild` also drive the loader bar — keep that contract if you refactor.

## 6. PWA

### Service worker
- `CACHE_NAME = 'pdfyz-v36-imposition-graphics'` — **bump it on every shipped change** (currently at v36).
- Install: tolerant pre-cache.
- Activate: cleans old caches, `clients.claim()`.
- Fetch:
  - `POST /PDF-YZ/` → share_target: stash file in cache `pdfz-share` at `/PDF-YZ/__shared__`, redirect 303 to `/PDF-YZ/?share=1`.
  - Navigation → network-first, fallback to cached `index.html`.
  - Other → cache-first, opportunistic refresh.
- Listens for `{type:'SKIP_WAITING'}` from the page.

### Manifest
- `scope` & `start_url` `/PDF-YZ/`, `display: standalone`.
- `file_handlers`: `application/pdf`.
- `share_target`: POST multipart, file param `pdf`.

### Install flow (top-right `#btnInstallPwa`)
1. Always visible (CSS `display:flex`, hidden via `.is-hidden` only in standalone).
2. Click → `ensureDonationOrSkip()`:
   - If `localStorage['pdfz_donated_v1'] === '1'` → skip directly to native prompt.
   - Otherwise show `#pdfz-donate-overlay` (PayPal subscription, plan_id `P-56T2084300778262ANHT2W4Y`, vault+subscription).
   - Promo code field — valid codes hardcoded in `VALID_CODES` at [index.html:6419](index.html#L6419) (currently `['808316']`).
3. After unlock → `deferredPrompt.prompt()` (Chromium) or manual instructions alert (iOS / Safari / Firefox).

### Pre-home (splash) — layout & session list
The screen is a **wide two-pane shell** (`.splash-shell`, up to 1320 × 760 px), not a small centred card:

```
┌──────────────────────────────────────────────────────────────┐
│ [logo] PDF-YZ                                                │  .splash-header
│        Edit, annotate, arrange & export PDFs …               │
├──────────────────────────┬───────────────────────────────────┤
│  ┌────────────────────┐  │  PREVIOUS SESSIONS  (n)  [🔍][All] │  .splash-resume
│  │   drop zone        │  │  ┌──────────┐ ┌──────────┐         │
│  └────────────────────┘  │  │ doc A  ▶ │ │ doc B  ▶ │         │  .splash-sessions
│  [ Open PDF ][ Blank ]   │  └──────────┘ └──────────┘         │   (grid)
└──────────────────────────┴───────────────────────────────────┘
```

- `.splash-body` is a grid `minmax(300px,380px) 1fr`; below 900 px it stacks and the body scrolls,
  below 560 px the session grid becomes a single column and the search field disappears.
- There is **no footer badge** any more (`v1.0 · 100% offline · © zigmoon.com` was removed on purpose).
- The session list is a **card grid** (`repeat(auto-fill, minmax(236px, 1fr))`), each card being a
  3-column CSS grid: `icon | title | actions` over `icon | meta | meta`.
- Each card shows `Ready` / `No PDF`, age, page count and payload size, plus **Resume** (only when the
  payload exists) and ✕ *Forget*. `Enter`/`Space` on a focused card resumes it.
- Search field appears only when more than 3 sessions; `All` opens the full `#sessionsModal` popin,
  which uses the same helper and disables *open* on rows without a payload.
- **Resume** calls `restoreSession(id)`:
  1. payload from IndexedDB (`pdfyz-sessions` / `docs`);
  2. fallback to the legacy `pdfz-meta` + `pdfz-pdf` slot when the file names match;
  3. otherwise a toast explains the PDF is gone — the list never pretends otherwise.
- While a document loads, `#splash` gets `.splash-busy`: the drop zone and the buttons are replaced by
  the progress card and the session pane is dimmed with `pointer-events: none`, so a second resume
  cannot be launched mid-load. `_setSplashBusy()` is the single place that toggles it
  (`showLoader` / `hideLoader` / `beginSplashProgress` / `endSplashProgress` / `btnNewDoc` all call it).
- `openPDF()` registers the session index entry right after the bytes are read, so a tab closed during
  the render pass still leaves a resumable row.

## 8. Tools / features

| Tool | Activation | Notes |
|---|---|---|
| Select | `V` / toolbar | default. Selects **every** element: extracted text, inserted image/signature, extracted PDF object (line/rect, thin rules included) and every freehand/highlight stroke |
| Text | `T` | extracted text = inline-edit overlay; user text = draggable box. **One click on any text block opens the panel + the inline editor** (drag >5px = move) |
| Image | `I` | from file input; auto-selected with corner handles, proportional resize (Shift = free) |
| Draw | `D` | freehand on `drawLayer`; each stroke becomes a selectable `.el-stroke` object. **Shift = one straight horizontal/vertical stroke** snapped from the stroke origin (the layer is repainted so nothing unconstrained is left behind) |
| Highlight | `H` | 30 % alpha by default; colour chosen in the colour popover; same Shift constraint |
| Eraser | `E` | wipes drawn paths |
| Signature | toolbar | capture modal with an **Ink** colour row; the colour is baked into the transparent PNG |
| Note | annot FAB / toolbar | sticky note overlay |

**Proportional resize**: images, signatures, PDF images **and freehand strokes** scale uniformly from a
corner handle (the axis dragged the most in *pixels* drives the scale); Shift re-enables free resizing.
Stroke resizing rescales `path.points` and the pen width, so the drawn line keeps its proportions.

**Colour popover** (`#colorPop`): opens when *Draw* / *Highlight* / *Signature* is picked (tool colour) and
whenever an object that owns a colour is selected (text block, sticky note, extracted PDF object,
freehand/highlight stroke, signature). Selecting a stroke recolours it in place; selecting a signature
re-tints the transparent PNG (a scan without alpha is left untouched with a toast). The selection flows
through `selectEl()` → `openColorPopForSelection()` → `colorizeElement()`.
It is a **draggable widget**: drag its header to move it; the position is clamped to the viewport and kept
in `localStorage['pdfz-colorpop-pos']` (`positioned` class replaces the centred transform).

**Z-order inside `.edit-layer`** (CSS, per element): extracted PDF graphics `1` · extracted PDF image `2`
· extracted text hit-area `3` · user image/signature/stroke `4` · user text `5` · note `6`. Without this
order the opaque background rectangles recovered by `extractPageGraphics` landed **on top of** the text
drawn over them and swallowed every click.

**Extracted vector objects** (`extractPageGraphics`, `graphicKind: 'path'`): every painted `constructPath`
is captured as a list of **subpaths** (`pdfSubpaths`, PDF points; beziers flattened to 10 segments), not
just isolated lines/rects. Rules drawn as thin filled rects, block outlines, dashed frames and compound
paths are therefore selectable/movable/recolourable/deletable.
- One element per *painted path* (all its subpaths grouped). `el.fillColor` and `el.strokeColor` are kept
  separately — a yellow shape with a brown outline must not become brown.
- `_graphicSigs` (per page) drops **identical paints**: some PDFs draw the same object twice, which used to
  leave stacked copies the user had to delete one by one.
- Hit-testing is done by a fat transparent copy of the path (`.graphic-hit`, `pointer-events: stroke`, or
  `all` when filled) — a diagonal outline must not swallow clicks over its whole bounding box.
- `bgColor` is sampled **around** the object (`sampleSurroundColor`), never at its centre: a centre sample
  returned the object's own colour, so deleting it repainted it in its own colour and it "could not be
  removed".
- Export draws the shape with `page.drawSvgPath()` in SVG space (`y = pageHeight - pdfY`, anchored at
  `(0, pageHeight)` because pdf-lib flips the SVG y axis): a mask in `bgColor` first (fill or thick stroke),
  then the moved/recoloured shape. Legacy `pdfPoints` elements are normalised by `graphicPdfSubpaths()`.
- `viewSubpaths` are cached on non-enumerable properties; invalidate them (`invalidateGraphicView`) after a
  re-render, a page transform **or a move** — a stale cache painted the shape at the wrong offset while it
  was being dragged. `refreshGraphicGeometry()` re-projects the preview and its hit copy in place.
- **Stacking is never changed by touching an object.** `placeElement()` used to `appendChild()`, so every
  re-place lifted the node to the end of the layer: a background ended up drawn above the logo and the text
  it sat under. `_insertInModelOrder()` now re-inserts at the model index (`S.pages[n].elements` order is the
  PDF paint order).
- **A flat erase mask hides whatever was drawn above it.** `_refreshMaskedOverlaps()` flags every extracted
  graphic/image that intersects a mask with `.under-mask`, which forces its vector preview to `opacity: 1`:
  moving a background no longer swallows the logo paths, the rule and the picture that sat on it.
- **Recolouring keeps two-tone objects two-tone**: `colorizeElement()` only touches the channel the object
  paints (fill when filled, stroke when stroke-only). `objectColor()` reports the same channel, so the
  colour popover shows the colour it is about to change. `bgColor` (the mask colour) is never reused as a
  fill — that is what made a deleted object repaint itself.
- The export repeats the same order: after a graphic mask it redraws the extracted graphics **and the text**
  that intersect it (second pass, `inkMasks` / `coveredByMask`), otherwise the mask erased the text laid over
  a moved background from the written file. Font resolution is shared with the normal text branch through
  `_exportFontFor()`.

**Export** ([4633](index.html#L4633)): Standard / PDF-A / Print-ready, flatten, embed fonts, watermark, crop marks, ICC embed, page resize (A4/Letter/Legal), DPI 72/150/300/600, compression none/light/aggressive.

**Imposition** (`calculateImpositionOrder`, `buildImposedSides`, `applyImposition`): two modes.

- **Booklet / signature** (default) — the **SuperPrint order**, ported from `superprint/app/JS/main.js`
  (`calculateImposition`). The job is padded to a **multiple of 4** (blank padding pages exist only on the
  sheets, the document is *never* modified), then the pages are paired outer-first:
  `4 pages → [4,1] [2,3]` · `8 pages → [8,1] [2,7] [6,3] [4,5]` · `20 pages → [20,1] [2,19] [18,3] [4,17] …`
  Recto puts the high page on the left, verso puts the low page on the left, so a duplex print
  (“flip on short edge”) folds into a booklet. One imposed side = **one page of the new document**.
  `impoBinding = perfect` pairs sequentially instead: `[1,2] [3,4] …`.
- **N-up grid** — the page sequence in reading order, 4/8/16/20/24/32/64 slots per sheet, padded to a
  multiple of 4 as well.

`Sheet size = auto` means **2 × the first selected page** in booklet mode (so the pages come out at
100 %), the page size itself in N-up mode. The modal shows the exact print order (`#impoOrderList`) and a
live sheet diagram using the real page numbers, so the preview can never disagree with the output.

**Find & Replace** ([5378](index.html#L5378)): regex, prev/next, replace one/all.

**PDF → .sp (SuperPrint)** (`convertToSP`): two modes — *image only* (one rendered image per page) and
*image + editable text* (each extracted text block becomes a Fabric `textbox` on top of a mask `rect`).
Coordinates are **PDF points** because SuperPrint's `mmToPx = mm * 72 / 25.4`; only `top` is flipped
(`top = pageHeightPt - pdfY - 0.8 * fontSize`). A block only becomes editable when the pixels around
it are a FLAT colour (`spProbeBackground`), otherwise it stays part of the page raster. Google Fonts
used by the text are embedded in `resources.customFonts` as `data:font/woff2;base64,…`.

**The textbox width must be the width the text will REALLY take in the substituted font**, not the
original PDF width: `measureSpTextWidth()` (canvas `measureText`, after a `loadGoogleFont()` preload
pass) gives that width, the box is `max(pdfWidth*1.10, measured + 0.2*fs)` and, when the substitute is
wider, the object is **condensed with `scaleX = origW / boxW`** (Fabric scales around originX/originY =
left/top, and SuperPrint's loader does pass `scaleX` to `new fabric.Textbox`). The mask stays
`origW + 3` wide, so it always covers the baked-in original. Without this the text wrapped and spilled
out of its mask — measured on the press kit's `SUPERPRINT.cc` wordmark: source 377 pt (condensed face),
substitute `Bebas Neue` **520 pt (+38 %)** in a 423 pt box → 2 lines, overlapping the logo and the next
line, which read as “the logo was duplicated”.
See `AUDIT-CONVERTISSEUR-SP.md` for the format proof (validator, units, loader).

## 9. Conventions for editing this codebase

- **Single file**: keep CSS in the existing `<style>` block, JS at the bottom of `<body>`.
- **Use the `S` object** for state. Never introduce parallel global state.
- **Use `$('id')`** (helper at top of script) instead of `document.getElementById`.
- **Use `toast(msg)`** for transient feedback. Toasts are **top-right** (`#toastZone`, under the floating
  export button) — never at the bottom, where they used to cover the canvas. Keep messages **short
  (one line, < ~45 chars)** and don't toast on things the UI already shows (a new text block, a note,
  a selection): a toast on every click is what made the app feel noisy.
- **Use `_uiYield()`** in any loop > ~50 iterations to avoid freezing.
- **Use `markDirty()`** after any user-visible change so autoSave fires.
- **A text block placed with the Text tool is PROVISIONAL** (`el._provisional`, tracked in
  `S._provisionalEl`): it is rendered so the insertion point is visible, but it is **not** in
  `S.pages[].elements` until something is typed. `commitProvisionalText(el)` (called from the panel
  textarea, the inline editor and `endInlineEdit`) makes it real; `discardProvisionalText(el)` throws
  it away silently (no toast, no history step, never exported). Called from `dropEmptiedBlock`,
  `addText` (one click = at most one block) and `setTool`. **Never `pushUndo` a provisional block.**
- **Annotations are objects**: `S.pages[].paths` stays the single source of truth for freehand/highlight
  strokes (the export reads it), and `syncStrokeOverlays(pageData)` — called from `redrawPaths()` — mirrors
  each path as a `.el-stroke` hit-area in `editLayer` with its own resize handles. Any code that mutates
  `paths` must go through `redrawPaths()` so the overlays follow. Path coordinates are **screen**
  coordinates and are rescaled on zoom/rebuild.
- **Do not put extracted graphics above text.** PDF objects are recovered *after* the text overlays, so
  their DOM would naturally sit on top; the CSS z-order in `.edit-layer` is what makes text-on-background
  clickable. Keep new element types inside that ladder.
- **Strings**: two layers — the **toolbar tooltips / `#moreDrop` labels / mobile mirror / `.sp` modal are French**
  (matching the pre-existing French mobile toolbar); the **desktop panels** (Edit Text, Export, Imposition,
  Preferences…) are **English**. Don't mix languages inside one panel or one menu.
- **Editing text on the page is a SINGLE click.** Any text block (extracted or user-added) sets
  `dom._wantEdit = true` on mousedown; the `click` listener on the block then calls `startInlineEdit`
  (on `click`, i.e. after `mouseup`, to avoid a focus race). A drag (>5px) moves the block instead.
  Double click is only a fallback. Do **not** reintroduce a double-click requirement — that was the
  main reason text editing felt undiscoverable.
- **Z-index ladder**: splash 999999 · install button 1000000 · donate overlay 1000001 · loader 999990. Don't insert above 1000001 without reason.
- When changing cached assets, **bump `CACHE_NAME` in service-worker.js** (`pdfyz-v36-*` → next number).
- **Two audit scripts live next to `index.html`** (run them before shipping):
  `node _audit-dom.cjs` → ids referenced by JS but absent from the markup, duplicated ids;
  `node _audit-code.cjs` → duplicate/dead declarations, leftover `console.log`, empty catches, TODO markers.
  Both must report 0 for the first two categories.
- **Never revoke a download URL synchronously** after `a.click()` (the browser may not have started
  reading the blob yet — large exports can fail). Revoke on a timer instead.
- Don't add SRI to PayPal SDK — its URL changes; keep CDN dynamic load.

## 10. Known issues / risks

- **PDF/A forbids non-embedded fonts.** `exportPDF()` therefore ignores the *Embed fonts* preference
  when `prefs.standard === 'pdfa'` (`!prefs.embedFonts && !isPdfa`) and toasts
  `PDF/A: fonts embedded (required)`. Measured before the fix: 159 KB PDF/A advertising `pdfaid:part=2`
  while shipping `/Subtype /Type1 /BaseFont /Helvetica` **without** a FontFile → not valid PDF/A
  (pdfcpu's strict check does not catch it; veraPDF would).
- **Exports are deterministic** except `/CreationDate` + `/ModDate` (14 s apart ⇒ 3 413 differing bytes
  inside one `/ObjStm`). Sizes stay identical, so a byte-count comparison is a valid regression test.
- **Audit 2026-10-04 → `RAPPORT-AUDIT-2026-10-04.md`** and **`RAPPORT-TESTS-2026-10-04.md`**.
- **PDF/A is a real feature now.** `prefs.standard === 'pdfa'` writes an XMP identification
  (`pdfaid:part=2`, `conformance=B`, dc:*, xmp dates), a `/Lang` **string** in the catalog, and a
  mandatory **OutputIntent** with `S = GTS_PDFA1` + an embedded ICC profile (falls back to the
  generated sRGB when none is selected). Validated with `pdfcpu validate --mode=strict` → **ok**.
  Two latent type bugs fixed on the way: catalogue `/Lang` and the OutputIntent strings
  (`OutputConditionIdentifier`, `RegistryName`, `Info`) were written as **Names** instead of
  **Strings** — that also affected the plain “embed ICC profile” path. Info dates are normalised
  to `D:YYYYMMDDHHmmSS+HH'mm'` because pdf-lib's `…Z` form is rejected by strict validators.
- **Print**: `printPDF` keeps its iframe alive until `afterprint` (a fixed 5 s timer used to race
  with the print dialog).
- **Touch**: signature + freehand drawing verified with real touch input (CDP) — Pointer Events work.
- **The four export settings are real now** (they used to be inert):
  - *Resolution* (72/150/300/600 DPI) caps the resolution of the raster pictures the export
    embeds (`optimizeRasterForExport`, applied to user images & signatures only — never to the
    source PDF's own pictures).
  - *Compression* `none` → rasters untouched; `light` (default) → only resample pictures more
    than 25 % oversized for the chosen DPI; `heavy` → always bring them down to that DPI and
    re-encode JPEG sources at *Image quality*. A PNG is never turned into a JPEG and an
    optimisation is skipped whenever it would grow the file.
  - *Image quality* drives that JPEG re-encode (and the flattened page images).
  - *Flatten to image* (`flattenDocumentToImages`) rebuilds the finished document as one image
    per page: nothing stays editable/selectable and the original text disappears from the file.
    **Default OFF**, with a one-time migration (`pdfz-flatten-migrated`) because the old toggle
    was inert and defaulted to ON — leaving it on would have silently rasterised everyone's exports.
  - The export summary + the final toast report what actually happened (e.g. « 300 DPI · aplati ·
    1 image rééchantillonnée · 579 Ko économisés »).
- **Known issues / risks**
  - **4 export settings were inert until 2026-10-04** — implemented, see above; the DPI read by the
    export dialog comes from the dialog itself, not from `prefs.dpi` (which is only synced on Export).
  - PDFs ≥ 10 MB are not persisted (`savePdfBytes` bails out silently); the session row then shows
    **No PDF** with only its *Forget* action, so it can no longer advertise a payload that was never stored.
  - `ignoreEncryption: true` opens protected PDFs and re-saves them **without** their
    protection, without warning.
  - pdfcpu reports an empty `/Annots []` array per page (inherited from the source PDF).
- **Service Worker must never reload the tab on its own.** `controllerchange` previously called
  `window.location.reload()` unconditionally, which killed in-flight work (an export was lost this
  way). It now requires `_swReloadRequested` (set only by the update toast's *Reload* button).
- **Auto-save failures are surfaced** (`_notifySaveFailure`) — a full localStorage used to fail
  silently while the user kept working.
- **Empty text blocks are dropped** (`dropEmptiedBlock`): an emptied block used to stay as an
  invisible box that still captured clicks. The empty state is never recorded in history, so a
  single Ctrl+Z brings the original text back.
- **Undo/Redo**: snapshot-based (see §2) and covers add / delete / move / resize / draw / erase / text + color edits. `resetHistory()` runs at the end of `openPDF` / `rebuild`.
- **Touch input**: draw / highlight / eraser / signature / drag / resize all use **Pointer Events** (`setPointerCapture`, `touch-action:none`).
- **Typography on import**: pdf.js only exposes an internal font id (`g_d0_f1`). The real name comes from `pdfJsPage.commonObjs.get(item.fontName).name` (populated because `page.render()` runs before `extractPageText`). Do not pass the raw id to `detectFont`.
- **Typography on export**: pdf-lib **requires** `doc.registerFontkit(window.fontkit)` (helper `registerFontkitOnDoc`). Without it every `embedFont(bytes)` throws and text silently falls back to Helvetica. `@pdf-lib/fontkit` is loaded via `<script>` next to pdf-lib. Google Fonts only serves **woff2** nowadays — fontkit decodes it fine. `_fontSubs` warns the user when a substitute was needed.
- **Concurrent renders**: `renderAllPages` re-creates every canvas; a second pass launched while the first is running leaves **blank pages**. Guarded by `_renderBusy` + `_pendingZoom` (a zoom requested during a render is applied once it finishes). `setZoom` and the `resize` auto-fit handler must keep respecting them.
- **Hidden tab = frozen render**: pdf.js drives `page.render()` through `requestAnimationFrame`; in a background tab the promise never resolves (no error, no paint). When driving the app with Playwright, assert `document.visibilityState === 'visible'` first, otherwise `extractPageText` is never reached.
- **`ignoreEncryption: true`** in `PDFDocument.load()` (lines 2785, 2848, 4192) silently bypasses encrypted PDFs — security attributes are dropped on save.
- **localStorage 10 MB cap**: PDFs > 10 MB are not persisted. No fallback to IndexedDB.
- **Promo code in clear**: `VALID_CODES` is publicly readable — security theater only.
- **No SRI** on any CDN script — supply-chain risk.
- **Accessibility**: canvas interactions aren't keyboard-reachable; no alt text. ARIA labels are present on buttons/regions though.
- **`sampleTextColor` / `sampleBgColor`** are the dominant cost in `extractPageText` — further optimization would target them (sample fewer pixels, batch).
- **Signature modal** is wired in the UI but verify the captured signature actually flows into `exportPDF` before promising the feature.
